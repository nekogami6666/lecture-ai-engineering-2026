# 第5回 宿題：検索件数と回答の比較

## 基礎

公式第5回のコミット `88b420adb5c8fbfe03dba26958658b0be6f28587` の同梱SQLite索引を使用。索引の再構築なし。質問、モデル `gemini-3.5-flash-lite`、資料、通常のベクトル検索を固定し、`app/config.py` の `RAG_TOP_K` のみ5→2へ変更。各条件で新規プロセスから1回ずつ `uv run --frozen python -m app.agent --trace` を実行した。

質問：第2回の説明では、LoRAは何を固定し何を学習しますか？ QLoRAは何を加えますか？

| 実測 | 変更前：5件 | 変更後：2件 |
| --- | --- | --- |
| ツール呼び出し | `search_materials` 1回。検索語：LoRA 固定 QLoRA 追加 | `search_materials` 1回。検索語：LoRA 固定 学習 QLoRA 加える |
| 回答の要点 | 元の重みを固定し、低ランクの追加差分だけを学習。QLoRAは元の重みを4ビット量子化 | 同じ要点。2つの小さな行列の積で表す差分を学習することを説明 |
| 根拠 | 回答の引用は第2回PDF p.51・52。検索のtraceで最初に見える結果は `lec02-main-p052` | 同じ引用ページ。検索のtraceで最初に見える結果も `lec02-main-p052` |
| 応答まで | 3.16秒 | 2.44秒 |
| 入力／出力トークン | 3,117／205 | 1,741／170 |
| モデル応答回数 | 2 | 2 |
| CLI表示の生成API推定費用 | $0.001448 USD | $0.000947 USD |

CLIの費用は埋め込み・索引構築を含まない表示上の推定値で、請求額ではない。実行はGeminiの無料枠のプロジェクトで行った。

### 気づき

今回の質問では、検索件数の上限を2件にしても核心と引用が維持され、入力が約44%減った。一方、モデルが作った検索語も異なるため、差を検索件数だけの効果と断定できない。traceでは通常検索の戻り値が省略表示されるため、見えた先頭結果と回答が引用した全ページを区別した。次に検証するなら、検索語も固定した比較と、離れた複数ページを必要とする質問を追加する。

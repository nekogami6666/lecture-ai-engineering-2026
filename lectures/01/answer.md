# 第1回 解答

## 演習

- 講座に固有の質問（宿題の3レベル）へのモデルの回答：実APIは未実行。利用可能な環境変数 `GEMINI_API_KEY` がないため、実際の回答は記録していない。
- 用語集の正しい意味：基礎・実装・発展の3段階で、いずれか1つに取り組めばよい。会話履歴の保持は過去の発言を引き継ぐ仕組みであり、講座の正しい情報を自動で取得する仕組みではない。モデルの回答の正しさは別途資料と照合する必要がある。
- 表示できたトークン数（入力 / 出力）：単体テストの模擬応答では `12 / 7` の表示を確認。これは実APIの実測値ではない。usageがない場合は0とせず「不明」と表示する。

## 宿題

- 取り組んだレベル：実装
- やったこと：`app/ask.py` に `--chat` を追加した。質問を `user`、回答を `model` として履歴に保持し、次の質問と一緒にAPIへ送る。`/reset` で履歴消去、`/exit` またはEOFで終了する。既存の単発質問も利用できる。
- 結果：Python 3.12.3、固定依存環境で `uv run --frozen pytest -q --tb=short` を実行し、既存テストを含む20件すべて成功した（2026-11-02）。追加した9件では、2問目に1問目と回答が含まれること、APIエラー・空回答で履歴が変わらないこと、空入力、usage欠落、resetと終了を確認した。実APIでの回答品質とトークン実測は未確認。
- 気づき・疑問：文字列を連結するだけでなく、発言者を区別したContentを送ることが重要。モデルの応答Contentをそのまま保存して署名などの付随情報も保持する。エラー時に質問だけ追加すると会話が不整合になるので、成功後に質問と回答をまとめて追加した。会話が長くなると送信する履歴と入力トークン数が増えるため、将来的には要約や履歴長の制限も必要になる。

## 実行方法

```bash
uv sync --frozen
uv run pytest -q
uv run python -m app.ask --chat
```

APIキーは環境変数だけで渡す。履歴はプロセス内のみで保持し、ファイルには保存しない。AI支援を利用して実装・テストを作成した。

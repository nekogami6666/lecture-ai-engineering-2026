## 演習

### 素のLLMとの違い

第1回の `app.ask` と第3回のエージェントの実回答比較は未実施。構造上の違いとして、エージェントには用語集の検索と講義要点の取得があり、その結果を次のモデル要求に返せる。資料を参照しないモデル応答と違い、講座固有の情報を根拠にできる。ただし、ツールが存在することと、実モデルが適切な引数で呼び出し正確に回答することは別なので、オフライン検証だけで回答品質の改善を断定しない。

### 追加した確認問題ツール

`make_quiz(lecture: int) -> str` を作成し、エージェントに登録した。指定回の用語を1つ選び、その用語の定義を正解として JSON で返す。存在しない回や第0回では例外で停止せず、用語がないことを返す。

docstring には、復習問題を頼まれたときに使うこと、講義番号は1始まりであること、問題を先に出して解答後に正解を示すことを書いた。`INSTRUCTIONS` にも確認問題ではこのツールを使う指示を追加した。`--list-tools` では既存2ツールと合わせて4ツールが見えることを確認した。実モデルによる出題内容や正解の提示タイミングは未検証。

### ツール呼び出しと回数の記録

保存の承認フローは、固定のツール要求を返す FunctionModel で再現した。実際に記録した呼び出しは次のとおり。

```text
save_learning_log({
  'title': '第3回の確認',
  'content': '保存前に利用者の承認を求め、拒否された場合は保存しない。'

```

承認待ちになった時点では `requests=1`、保存先ディレクトリは未作成だった。`y` で再開した場合は `saved=true` が返り、ファイルが1件作られた。`n` または空入力では拒否結果が会話に戻り、ファイルは0件だった。いずれも最終的な `requests=2` はテスト用モデルの要求回数であり、実LLMの呼び出し回数ではない。トレース中の入出力トークン数も FunctionModel の推定値であり、利用料金の見積もりには使わない。

## 宿題：承認付き学習記録の保存

### やったこと

1. `save_learning_log(title, content)` を `requires_approval=True` で登録し、出力型に `DeferredToolRequests` を追加した。ツール要求が来ても、この時点では保存処理を実行しない。
2. CLI で保存先とタイトル・本文の全体を表示し、呼び出しIDごとに確認する。`y`、`yes`、`はい` の明示入力だけを承認し、空入力・曖昧な返答・EOF・Ctrl-C は拒否として扱う。
3. 判断を `DeferredToolResults` に入れ、`message_history=result.all_messages()` と一緒に `run_sync` へ渡す。モデル要求数は再開前後で累積し、無限の再要求を防ぐため確認回数とモデル要求数に上限を設けた。
4. 保存先は `learning_log/` に固定した。タイトルをファイル名に使わず UUID で新規作成し、既存ファイルは上書きしない。ディレクトリのシンボリックリンクを拒否し、開いたディレクトリの記述子を基準にファイルを作る。作成したファイルは所有者だけが読み書きできる権限にした。
5. 空文字・長すぎる入力を拒否し、書き込み失敗時には不完全なファイルを除く。学習記録の本文は `.gitignore` の既存設定により提出リポジトリへ含めない。

### 結果

既存テスト11件に、境界値・例外・承認の組合せを含む36件を追加し、**合計47件が成功**した。

| 確認した条件 | 結果 |
|---|---|
| SDKが承認待ちを返した直後 | ディレクトリ・ファイルを作らない |
| 明示的な承認 | 1件だけ保存し、その結果をモデルへ返す |
| 拒否・空入力・曖昧な入力 | 保存しない |
| EOF・Ctrl-C | 同じ待機中の未確認呼び出しをすべて拒否する |
| 複数の保存要求 | 呼び出しごとに確認し、承認したものだけ保存する |
| 次のラウンドの保存要求 | 前回の承認を流用せず再確認する |
| 保存拒否後に要求が繰り返される | 確認上限で停止し、未承認の保存をしない |
| 同じタイトル・ファイル名の衝突 | 過去の記録を上書きしない |
| タイトルに `../`、保存先がシンボリックリンク | 保存先を逸脱しない |
| 空・文字数超過・書き込み失敗 | エラーを返し、不完全な記録を残さない |
| `make_quiz(2)` | 第2回の用語とその定義を使う |
| `make_quiz(0)` など存在しない回 | 例外で落ちず、用語がないことを返す |

### 気づき・残る確認

「保存前に確認する」とモデルへ指示するだけでは、実行を止める仕組みにならない。承認が必要なツールとして登録し、実行側で許可を受けることが重要だった。また、モデルの文章に「保存した」と書かれていても、実際のツール結果とファイルの有無が一致しなければ完了とはいえない。

拒否後もツールの結果を会話へ戻すことで、モデルに「保存しなかった」ことを伝えられる。複数の保存要求をひとまとめに承認せず、呼び出しIDごとに扱うことで、許可の対象も明確になった。

本実装のファイル操作は Linux / Codespaces を対象とし、`dir_fd`、`O_DIRECTORY`、`O_NOFOLLOW` を利用する。プロンプトやdocstringが実モデルのツール選択にどう影響するか、自然文の保存内容が適切か、実APIでのレイテンシ・トークン数は未検証である。実APIの利用可能な環境では、通常質問・保存依頼・拒否後の応答を確認する必要がある。保存内容に秘密情報を含めない最終確認は利用者が行う。

## 再現方法

```bash
uv sync --frozen
uv run pytest -q
uv run python -m app.agent --list-tools
uv run python -m scripts.demo_learning_log
```

再現スクリプトは一時ディレクトリに合成データを保存し、終了時に削除する。実際の学習記録は作らない。

今回の実行環境では既定の `~/.cache/uv` が読み取り専用だったため、検証時だけ書き込み可能なキャッシュへ変更した。既存のMCPテストは子プロセスにも `uv` を起動するため、同じキャッシュ設定のローカルラッパーを PATH に置いて実行した。リポジトリの依存ファイル、MCP設定、既存テストは変更していない。
